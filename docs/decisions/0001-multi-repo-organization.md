# ADR-0001 从第一天起采用多仓库组织

| 项 | 内容 |
| --- | --- |
| 状态 | 已接受 |
| 日期 | 2026-11-14 |
| 决定人 | 项目发起人 |

## 背景

WaiShe 由 Dashboard、Bridge、驱动 SDK、Registry 和若干驱动组成。项目希望第三方能在独立仓库维护驱动，并让各组件独立发布。

规划时评估过另一种做法：先在单个仓库里孵化，驱动接口 1.0 冻结后再拆分。理由是接口未稳定期，一次接口变更要跨多个仓库同步发版。OpenMouse 为类似问题维护了专门的跨仓库同步工作流。

## 决定

采用 GitHub Organization 加多仓库，从第一天起按下表划分。

| 仓库 | 内容 | 产出 |
| --- | --- | --- |
| `waishe` | 项目总文档、Web Dashboard | Dashboard 构建产物 |
| `waishe-bridge` | 本地程序 | Windows 安装包 |
| `waishe-driver-sdk` | 驱动接口规范、能力模型、驱动侧库、测试工具 | 规范文档、库 |
| `waishe-driver-registry` | 设备兼容表、驱动索引、收录流程 | 签名索引 |
| `driver-razer` | Razer 协议驱动 | 驱动包 |
| `driver-hyperx` | HyperX 协议驱动 | 驱动包 |
| `.github` | 组织简介、社区规范、默认模板 | — |

组织已注册：<https://github.com/WaiShe-Project>。

## 理由

- 驱动的独立性是产品的核心主张。官方驱动与社区驱动处在同样的位置，才能证明 SDK 和收录流程对第三方是够用的。
- 许可证按仓库区分（[ADR-0002](0002-licensing.md)），多仓库使边界清晰。
- 各组件的发布节奏和贡献者群体不同。

## 后果与缓解

| 后果 | 缓解 |
| --- | --- |
| 接口变更需要跨仓库协调 | 接口规范只在 `waishe-driver-sdk` 一处定义；1.0 之前允许破坏性变更，但每次变更都要升版本号，Bridge 与驱动各自声明所支持的接口版本 |
| 跨仓库的设计讨论无处安放 | 统一放在 `waishe` 仓库的 `docs/decisions/`；跨仓库议题在 `waishe` 仓库开 Issue |
| 本地联调繁琐 | 约定各仓库检出到同一父目录下，Bridge 的开发者模式可直接加载相邻目录中构建出的驱动包 |
| 社区文件重复 | 贡献指南、行为准则、安全策略、Issue 与 PR 模板放在 `.github` 仓库，由 GitHub 作为组织默认文件应用到各仓库 |
| 版本组合难以追踪 | Bridge 的发布说明列出它内嵌的 Dashboard 版本和支持的驱动接口版本范围；Registry 索引记录每个驱动版本要求的接口版本 |
| 仓库数量随品牌增长 | 驱动按品牌或协议族建仓，不按型号 |

## 调整余地

本表是初期划分。若 M0 之后发现某两个仓库总是同时修改，可以合并，并以新的决策记录说明。
