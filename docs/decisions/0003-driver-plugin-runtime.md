# ADR-0003 驱动插件运行时

| 项 | 内容 |
| --- | --- |
| 状态 | 提案，待 M0 验证项 S3 得出结论 |

## 背景

驱动要满足的需求：

- 独立开发、独立发布、按需安装、可更新可回滚（DRV-01、DRV-10 至 DRV-12）。
- 故障隔离：崩溃、超时、死循环不影响 Bridge（DRV-05）。
- 最小权限：只能访问被授予的设备句柄（DRV-06）。
- 支持设备主动上报（HEAD-04）。
- 运行时开销符合轻量化目标（PERF-01、PERF-03）。
- 同一驱动包将来可用于 Linux 和 macOS。
- 项目倾向用 Rust 写驱动。

驱动的工作负载是 I/O 密集型：一次 HID 往返是毫秒级，驱动自身的计算量很小。因此运行时的执行速度不是关键指标，体积、内存和隔离能力才是。

## 备选方案

| | A. WASM 沙箱 | B. 原生动态库 | C. 独立进程 + IPC | D. 内嵌脚本引擎 | E. 编译进 Bridge |
| --- | --- | --- | --- | --- | --- |
| 故障隔离 | 有。陷阱不影响宿主；可限制执行时间和内存 | 无。崩溃即 Bridge 崩溃 | 有。进程边界 | 有。可限制执行 | 无 |
| 最小权限 | 有。只有宿主提供的函数可调用 | 无。可执行任意代码 | 弱。原生进程可执行任意代码，需额外的系统级沙箱 | 有。只暴露受限 API | 不适用 |
| 一个包适用所有平台 | 是 | 否，每平台每架构一份 | 否 | 是 | 不适用 |
| 用 Rust 写驱动 | 是 | 是，但 Rust 没有稳定 ABI，需走 C ABI | 是 | 否，用 JS 或 Lua 等 | 是 |
| 独立分发与更新 | 是 | 是 | 是 | 是 | 否，违反 DRV-01 |
| 运行时开销 | 取决于具体运行时，需实测 | 最小 | 每个驱动一个进程 | 小 | 无 |
| 复用现有 TypeScript 协议代码 | 不能直接复用 | 不能 | 不能 | 引擎为 JS 时有可能 | 不能 |
| 先例 | — | — | — | BatteryMonitor 用 QuickJS 沙箱运行 HID 插件 | OpenMouse Bridge 的原生读取器 |

## 倾向

**方案 A：驱动编译为 WebAssembly，Bridge 提供一组受限的宿主函数（HID 收发、时钟、日志）。**

理由：它是唯一同时满足隔离、最小权限、单一跨平台产物、用 Rust 编写这四项的方案。B 和 E 不满足隔离与权限要求，直接排除。C 的权限控制需要另建系统级沙箱，且每个驱动常驻一个进程，与轻量化目标冲突。D 满足隔离与权限，但放弃了用 Rust 写驱动，作为退路保留。

接口用接口描述语言定义并版本化，驱动与宿主各自生成绑定，草案见 `waishe-driver-sdk` 仓库 `docs/driver-interface.md`。

## 未决问题

1. **用哪个运行时。** 候选包括带即时编译的成熟运行时和纯解释型的轻量运行时。前者功能完整（组件模型、执行中断、内存上限），体积和内存较大；后者体积小，由于负载是 I/O 密集型，解释执行的速度可以接受，但对接口描述语言与组件模型的支持程度需确认。
2. **接口形态。** 采用组件模型，还是手写的核心模块 ABI。前者工具链更好，后者能在更多运行时上运行。
3. **阻塞调用模型。** 驱动内的 HID 读取在驱动看来是同步调用；宿主侧用线程还是异步任务承载，影响每个驱动实例的内存。
4. **事件投递。** 主动上报由宿主读取输入报告后回调驱动。需确认回调与正在进行的读写操作之间的排队语义。

## M0 验证门槛（暂定）

用一个能在沙箱内完成“读取一次电量并监听一次静音事件”的最小驱动测量：

| 指标 | 门槛 |
| --- | --- |
| 运行时使安装包增加的体积 | 不超过 10 MB |
| 加载两个驱动后的 Bridge 常驻内存 | 不超过 40 MB（PERF-01） |
| 无调用时的 CPU 占用 | 为零 |
| 一次宿主 HID 调用的额外开销 | 不超过 1 毫秒 |
| 驱动死循环 | 能在设定时限内被宿主中止 |
| 驱动超量申请内存 | 被宿主拒绝，Bridge 不受影响 |
| 驱动加载耗时 | 不超过 200 毫秒 |

## 退路

按顺序尝试：

1. 换用更轻的 WebAssembly 运行时，必要时把接口降为核心模块 ABI。驱动仍用 Rust 编写。
2. 改用方案 D。驱动语言改变，SDK 与首批驱动需要重写；但可以重新评估直接运行 OpenMouse 的 TypeScript 编解码代码的可能性。

## 与许可证的关系

无论采用哪种运行时，驱动都是独立分发的包，[ADR-0002](0002-licensing.md) 的安排不变。
