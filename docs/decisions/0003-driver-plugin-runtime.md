# ADR-0003 驱动插件运行时

| 项 | 内容 |
| --- | --- |
| 状态 | 已接受（M0 验证项 S3，2026-11-14） |
| 日期 | 2026-11-14 |

## 背景

驱动要满足的需求：

- 独立开发、独立发布、按需安装、可更新可回滚（DRV-01、DRV-10 至 DRV-12）。
- 故障隔离：崩溃、超时、死循环不影响 Bridge（DRV-05）。
- 最小权限：只能访问被授予的设备句柄（DRV-06）。
- 支持设备主动上报（HEAD-04）。
- 运行时开销符合轻量化目标（PERF-01、PERF-03）。
- 同一驱动包将来可用于 Linux 和 macOS。
- 项目倾向用 Rust 写驱动。

驱动的工作负载是 I/O 密集型：一次 HID 往返是毫秒级，驱动自身的计算量很小。因此运行时的执行速度不是关键指标，体积、内存和隔离能力才是。

## 决定

**驱动编译为 WebAssembly 核心模块（`wasm32-unknown-unknown`），由 Bridge 内嵌的 wasmi 解释器运行；宿主与驱动之间使用手写的核心模块 ABI，不使用组件模型。**

- 驱动用 Rust 编写，可以是 `no_std`。
- 每个驱动实例一个独立的存储（store），内存上限独立设置。
- 计算时间用燃料（fuel）限制；阻塞型宿主调用（HID 读取、休眠）由宿主自身设超时。两者合起来约束一次调用的总时长。
- ABI 由 `waishe-driver-sdk` 定义并版本化，SDK 提供驱动侧的安全封装。

## 备选方案

| | A. WASM 沙箱 | B. 原生动态库 | C. 独立进程 + IPC | D. 内嵌脚本引擎 | E. 编译进 Bridge |
| --- | --- | --- | --- | --- | --- |
| 故障隔离 | 有。陷阱不影响宿主；可限制执行时间和内存 | 无。崩溃即 Bridge 崩溃 | 有。进程边界 | 有。可限制执行 | 无 |
| 最小权限 | 有。只有宿主提供的函数可调用 | 无。可执行任意代码 | 弱。原生进程可执行任意代码，需额外的系统级沙箱 | 有。只暴露受限 API | 不适用 |
| 一个包适用所有平台 | 是 | 否，每平台每架构一份 | 否 | 是 | 不适用 |
| 用 Rust 写驱动 | 是 | 是，但 Rust 没有稳定 ABI，需走 C ABI | 是 | 否，用 JS 或 Lua 等 | 是 |
| 独立分发与更新 | 是 | 是 | 是 | 是 | 否，违反 DRV-01 |
| 先例 | — | — | — | BatteryMonitor 用 QuickJS 沙箱运行 HID 插件 | OpenMouse Bridge 的原生读取器 |

B 和 E 不满足隔离与权限要求。C 的权限控制需要另建系统级沙箱，且每个驱动常驻一个进程。D 放弃了用 Rust 写驱动。A 是唯一同时满足四项要求的方案，M0 在 A 内部比较了两个运行时。

## M0 验证结果

环境：Windows 11（10.0.26100），Rust 1.100.0，wasmi 2.0.0，wasmtime 50.0.1（`cranelift`、`runtime`、`std` 特性），发布构建。两个原型驱动分别为 569 字节（Razer）和 716 字节（HyperX），通过宿主函数在真实设备上收发报文。

| 指标 | 门槛 | wasmi 2.0 | wasmtime 50 |
| --- | --- | --- | --- |
| 可执行文件增量（基线 263 KB） | ≤ 10 MB | **+2.2 MB** | +10.7 MB，不达标；加入组件模型后再 +45 KB |
| 加载两个驱动后私有内存增量 | Bridge 总计 ≤ 40 MB | +2.1 MiB | +2.9 MiB |
| 单个驱动编译并实例化 | ≤ 200 ms | 0.3–0.4 ms | 2.3–3.0 ms |
| 宿主调用额外开销 | ≤ 1 ms | 22 ns | 3 ns |
| 无调用时的 CPU | 为零 | 为零 | 时钟中断需要一个计时线程，原型中每 10 ms 唤醒一次 |
| 死循环 | 能被中止 | 燃料耗尽中止 | 时钟中断中止 |
| 中止后 | 实例可继续使用，其他驱动不受影响 | 是 | 是 |
| 超出 16 MiB 上限申请内存 | 被拒绝 | 是，`memory.grow` 返回 -1 | 是 |
| 访问未授予的句柄 | 被拒绝 | 是 | 是 |
| 沙箱内读取电量 | 成功 | Razer 89%，HyperX 47% | 同左 |
| 沙箱内等待设备上报 | 成功 | 收到静音键事件 | 同左 |

wasmi 的燃料按指令计，与时间的换算在原型中实测约为每毫秒 670 万单位，仅作量级参考，正式实现须按宿主函数的超时另行约束。

## 后果

- 无法使用组件模型及其工具链生成绑定。接口以核心模块的导入导出函数定义，由 SDK 维护文档、宿主实现和驱动侧封装三者一致。
- 解释执行比即时编译慢一个数量级，但驱动的计算量极小，实测单次 HID 往返的耗时由设备决定（Razer 约 51 ms，HyperX 约 2 ms），运行时开销可以忽略。
- 若将来出现计算密集的驱动或需要组件模型，可在不改变驱动包格式（仍为核心模块）的前提下换用其他支持核心模块的运行时。

## 已解决的未决问题

| 问题 | 结论 |
| --- | --- |
| 用哪个运行时 | wasmi |
| 接口形态 | 核心模块 ABI |
| 阻塞调用模型 | 驱动内的 HID 读取在驱动看来是同步调用，由宿主函数阻塞完成；原型中每个驱动实例在调用期间占用调用线程 |
| 事件投递 | 原型由驱动在调用内阻塞等待输入报告。正式接口改为宿主读取、回调驱动的 `on-input-report`，与读写在同一端点队列中串行执行，见 SDK 驱动接口文档 |

## 与许可证的关系

无论采用哪种运行时，驱动都是独立分发的包，[ADR-0002](0002-licensing.md) 的安排不变。wasmi 与 wasmtime 均为 MIT OR Apache-2.0 双许可，与 Bridge 的许可证一致。
