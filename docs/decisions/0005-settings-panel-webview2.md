# ADR-0005 原生设置面板用 WebView2 承载 Dashboard 的面板视图

| 项 | 内容 |
| --- | --- |
| 状态 | 已接受（需求待决事项 Q11，M1 原型实测，2026-11-14） |
| 日期 | 2026-11-14 |

## 背景

需求 APP-08 要求 Bridge 提供原生设置面板：不打开浏览器即可查看设备状态，并修改开机自启、低电量提醒、托盘显示策略，且与 Dashboard 的设置保持同步。界面技术需在体积（PERF-03）和私有内存（PERF-01）的约束下选定。

首发平台只有 Windows 11 x64（APP-09），而 Windows 11 自带 WebView2 运行时。

## 决定

**面板是 Bridge 创建的一个原生窗口，内嵌 WebView2，显示 Dashboard 的 `#/panel` 视图。**

- 窗口约 400 × 640，不可调整大小。托盘菜单“设置…”打开它；再次点击只把已有窗口带到前台。
- 窗口通过一次性授权码登录（`/auth?code=…&next=#/panel`），与 Dashboard 同样受 ADR-0004 的鉴权约束。
- 面板在第一次打开时创建。关闭时只隐藏窗口并卸载页面（导航到 `about:blank`），WebView2 进程保留，下次打开重新加载页面（2026-11-14 修订，见下文）。Bridge 退出时销毁。
- WebView2 的用户数据放在 Bridge 的本地数据目录下，不写入程序目录。
- 若窗口或 WebView2 创建失败，退回到用默认浏览器打开同一视图，并记录日志。

## M1 原型实测

环境：Windows 11（10.0.26100），wry 0.57.2，发布构建。

| 指标 | 结果 |
| --- | --- |
| 可执行文件增量 | +0.50 MB（6,485,504 → 7,012,352 字节） |
| 面板打开时 WebView2 进程的私有内存 | 约 170 MB，共 6 个进程 |
| 面板关闭后 | WebView2 进程全部退出，Bridge 私有内存不变 |
| 与 Dashboard 设置同步 | 在面板修改低电量阈值后，Dashboard 立即显示新值 |
| 重复打开 | 复用已有窗口 |

## 修订：关闭后保留 WebView2（2026-11-14）

原决定是关闭窗口即销毁 WebView。实测每次打开都要重新启动 WebView2，从点击到面板出现需 0.40–0.48 秒；窗口先于 WebView 显示还会白屏一下。项目发起人选择以内存换速度。

- 窗口创建时不可见，页面拿到设备数据后通知 Bridge（IPC 消息 `ready`）再显示；1.5 秒内没有通知也会显示，以便看到出错页面。
- 关闭时先隐藏窗口，再卸载页面，并把 WebView2 设为低内存模式；打开时恢复并重新加载页面。
- 页面卸载后没有事件流，Bridge 不会把隐藏的面板当作 Dashboard 连接而加快设备查询。

| 指标（Bridge 0.1.6 发布构建） | 结果 |
| --- | --- |
| 第一次打开（启动 WebView2） | 0.48 秒 |
| 之后每次打开 | 0.039–0.044 秒 |
| 面板隐藏时 WebView2 的私有内存 | 约 165 MB，共 6 个进程 |
| 面板隐藏时 WebView2 的工作集（实际占用的物理内存） | 约 49 MB |
| 面板隐藏时 Bridge 进程自身的私有内存 | 13.5 MB |
| 面板隐藏、无 Dashboard 连接时的设备查询间隔 | 耳机关机状态下 30 秒一次，即无人查看时的间隔（有人查看时为 5 秒） |

## 备选方案

| 方案 | 未采用的原因 |
| --- | --- |
| egui / Slint 等 Rust 原生界面库 | 设置界面要写第二套，与 Dashboard 分别维护文案、校验和交互；可执行文件增加数 MB |
| Win32 原生控件 | 体积最小，但界面需全部手写，同样要维护第二套 |
| 只打开浏览器 | 不满足 APP-08“不打开浏览器” |

## 后果

- 设置界面只有一套实现。面板视图由 `waishe` 仓库维护，随 Dashboard 一同内嵌进 Bridge。
- 面板第一次打开之后，WebView2 进程一直保留到 Bridge 退出，数值见上文修订。PERF-01 的 40 MB 只对 Bridge 进程自身成立；从未打开过面板时没有 WebView2 进程。
- 将来支持 Linux、macOS 时，需改用各平台的系统 WebView；wry 已覆盖这两个平台。
